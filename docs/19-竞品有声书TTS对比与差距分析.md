# 一、竞品定位与 TTS 能力盘点

## 1.1 微信读书（腾讯）

| 能力 | 具体表现 |
|---|---|
| 情感化朗读 | 基于 NLP 的**韵律预测**：悲伤段落语速放缓、激昂段落音调上扬，能模拟停顿、重音、**笑声** |
| 智能断句 | 语义级断句（意群切分），引号内对话**自动切换语气** |
| 音色库 | 多音色（性别/年龄/风格，如"温柔淑女"），按书籍类型推荐 |
| 听读一体 | 边看文字边听，朗读与文本高亮同步 |
| 技术 | 腾讯自研神经声学模型（云端推理），多音字、语气停顿、情感表达由模型端到端解决 |

## 1.2 番茄畅听（字节跳动）

| 能力 | 具体表现 |
|---|---|
| TTS 引擎 | 自研 TTS 3.0（字节 AI Lab，端到端神经网络 + 半监督字音判别），官方宣传 30~200+ 音色 |
| 方言音色 | 东北话、粤语、西安话、天津相声音色等 |
| 多角色 | AI 主播多角色配音（实测：**对话角色区分弱**，旁白尚可、对话出戏——行业共性问题） |
| 播放体验 | 0.5~2.0 倍速、定时关闭、睡眠渐弱、背景音效、CarPlay、断点续听、多端同步 |
| 覆盖 | 平台内几乎所有小说一键 AI 配音，解决冷门书无真人录制问题 |

## 1.3 Readify（悦读 AI）—— 与 votex 定位最接近

用户**自带电子书**转有声书（非平台书库模式），免费、无广告：

| 能力 | 具体表现 |
|---|---|
| 多格式导入 | EPUB / PDF（含扫描件直读）/ DOCX / MOBI / AZW / TXT / **网页（浏览器扩展）** |
| 音色库 | 100+ 逼真声音、50+ 语言，神经网络 TTS |
| **声音克隆** | **30 秒参考音频克隆任意声音**，设备端运行 |
| **多角色配音** | 为书中每个角色分配不同声音，"对话如广播剧" |
| 播放体验 | 倍速、文字高亮跟随、断点续听、多端同步 |
| 输出 | 实时流式朗读（点击即听，不必先生成整本书） |

## 1.4 共性结论

三家都做在了 TTS 能力之外的两层：**文本前端（断句/韵律/角色）** 和 **听书体验层（播放器）**。纯声学模型质量上，番茄/微信读书的云端大模型 > Readify 的端侧方案；Readify 的产品形态（本地导入 + 克隆 + 多角色 + m4b 式管理）与 votex 最可比。

# 二、votex TTS 现状（S1~S5 完成后）

**已具备**（对比三家不落后甚至更优）：
- 章节感知切分（第X章/回/卷/序章 + Markdown 标题）、m4b 章节封装（FFMETADATA，真实冒烟通过）
- 内联停顿标签 `[[pause:300]]`、段间静音、流式 WAV 拼接（段级内存，不驻留全书）
- 断点续转（session 目录 + 文本哈希校验）、可取消（token 全链路）
- 数字读法（整数/小数/百分号/逐位）、多音字词组消歧（~70 词组 + 一/不变调）
- 资源治理三层（ResourceMonitor / InferenceGate / 看门狗），批量模型复用
- 编码自动检测（GBK/UTF-8）、本地离线、隐私零上传、单二进制
- 引擎：Kokoro-82M-zh（多语种音色）、Qwen3-TTS、CosyVoice、**IndexTTS2（已实现 infra，支持零样本克隆）**

**尚未具备**（差距所在，见第三节）：文本前端 NLP 层薄、多角色、格式输入窄、播放/试听体验弱、无响度归一与语速后处理。

# 四、差距本质分析

## 4.1 三个层次

1. **声学模型层**（G2/G6）：竞品是云端千卡训练的大模型 + 大规模音色库；votex 用本地 ONNX 中小模型。这是**体量差距**，只能靠"本地最优 + 云端可选"绕开，不能硬追。
2. **文本前端层**（G1/G3/G4）：竞品的自然感一半来自 NLP/LLM 驱动的前端（断句、韵律、角色）。这一层**与模型体量无关，纯工程可实现**，是 votex 投入产出比最高的补齐方向。
3. **体验层**（G7/G10/G11）：竞品是"播放平台"，votex 是"生产工具"。但用户生成有声书后**必须有个地方听**——最小化补一个本地播放器即可，不必做书架/推荐/社区。

## 4.2 定位差异（明确不补）

- 内容生态/版权书库、AI 问书/大纲、社区互动、推荐算法、多端账号同步 —— votex 是**离线单机工具**，隐私与离线是核心卖点，这些属于平台型产品能力，不补。
- 云端大模型自研 —— 不自研，通过"在线 API 接入"（AGENTS.md 已规划 Azure/阿里云等）让用户按需换取云端音色，并在文档中明确隐私边界（用户文本内容默认不上传，云接入需显式开启）。

# 五、补全路线图（按投入产出比排序）

## T1 文本前端增强（对应 G1，★★★ 最高优先级）

- **语义断句**：在现有 `TextSegmenter` 上增加「引号对话整句保护」「意群切分（把字句/连词前不切）」「省略号/破折号不切断句子」。纯规则可解决 80%，规则表放 domain 层可单测。
- **对话语气感知**：检测引号内直接引语，向引擎传递 style/emotion 提示（Kokoro style 向量、Qwen3-TTS 情感参数已存在挂点）：叙述=中性、引语=生动。即使不完美，也比整本书一个语气好。
- **专名读音保护**：简单人名/称谓白名单 + 用户自定义发音词典（`[[ph:慕容复|mu4rong2fu4]]` 或词典文件），解决"慕容/复"类误切。

## T2 多角色配音（对应 G3，★★★ Readify 已验证是核心卖点）

- 引号内台词 ↔ 叙述检测（正则即可覆盖网文 90% 场景）。
- 角色表：可选 LLM 抽取（`角色 → 音色` 映射 JSON），或用户手填 `role_voice_map`。
- 合成时按段路由音色（Kokoro 多音色 / Qwen3-TTS 多说话人），段间用现有流式管线；输出 m4b 章节结构不变。
- 成本低：`build_synthesis_plan` 已返回段结构，只需给 `PlanSegment` 加 `voice: VoiceId` 字段。

## T3 格式输入扩展（对应 G5，★★★ Readify 的第一入口能力）

- **EPUB**：本质 zip + XHTML。Rust 纯实现：`zip` + `quick-xml`/`scraper` 提取正文 + spine 顺序 → 直接对接现有章节切分（EPUB 自带章节结构，比正则更准）。
- **DOCX**：zip + word/document.xml，同样套路。
- **PDF**：文本层用 `pdf-extract`/`lopdf`；扫描件走已有 PaddleOCR（已具备，缺一个"PDF 无文本层→自动转 OCR"的路由）。
- **网页**：粘贴 URL + 正文抽取（readability 算法，纯规则）。
- 输出统一为「章节化文本」进入现有 `build_synthesis_plan`，管线零改动。

## T4 声音克隆工作流补全（对应 G4，★★☆ IndexTTS2 已实现，只差产品化）

- 参考音频预处理：复用已有 denoise 能力（对应 E2A 的 DeepFilterNet 思路）。
- 克隆音色库：`voices/` 目录管理（参考音频 + 用户命名 + 试听），禁止自动删除、二次确认（符合 AGENTS.md 约束）。
- GUI：克隆页（录音/选文件 → 降噪 → 试听 → 保存音色）。
- 30 秒参考音频即可（IndexTTS2 支持零样本）。

## T5 音频后处理（对应 G9/G11，★★☆ 一次 ffmpeg 管线搞定）

- **响度归一化**：`ffmpeg loudnorm`（EBU R128）挂到 m4b/MP3 封装前，全书响度一致——竞品听感舒服的隐形因素。
- **合成端语速**：`atempo`（0.5~2.0，保音调）作为输出参数。
- **背景音混音**（可选）：`amix` 叠加环境音/BGM，做成流水线步骤（对接已有 pipeline 模板能力）。

## T6 本地听书播放器（对应 G7/G10，★★☆ 最小可用版）

- GUI 用现有 rodio 播放器扩展：**倍速**（rodio speed 控制）、章节列表跳转、播放进度记忆（SQLite 已具备持久化）、逐段高亮跟随（合成时每段 `start_ms` 已在 `ChapterTiming`，直接复用）。
- "边合成边听"：Streamer 每完成一段即把段文件加入播放队列即可，无需重写管线。

## T7 云引擎可选接入（对应 G6，★☆☆ 兜底项）

- 按 AGENTS.md 既定规划接入 Azure Speech / 火山引擎（豆包 TTS，番茄同源技术栈）/ 阿里云：`TtsProvider` trait 加云端实现即可，本地管线上层零改动。
- 必须显式开关 + 脱敏提示（文本上传第三方），默认离线。

## 建议节奏

| 批次 | 内容 | 理由 |
|---|---|---|
| 第一批 | T1 + T2 + T3 | 纯本地工程，改的是"自然度"与"入口"，性价比最高 |
| 第二批 | T4 + T5 | IndexTTS2 收尾成本低；loudnorm 一条命令级收益 |
| 第三批 | T6 + T7 | 体验兜底，先有最小播放器再谈流式 |

# 六、votex 应守住的差异化

竞品不可替代的部分，宣传与迭代都应围绕它们：

1. **完全离线 + 隐私**：书稿不上传，竞品（云端 TTS）做不到。
2. **文件→成品**：直接产出带章节的 m4b / MP3 / SRT，竞品是流式收听不给你文件所有权（Readify 除外）。
3. **可自动化流水线**：LLM 文案 + TTS + ASR 字幕 + 合成短视频（竞品均无）。
4. **资源治理**：低配机可跑、可断点续转、可批量——同类桌面工具（E2A）都不具备。
