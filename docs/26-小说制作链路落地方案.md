# 二、三个真实缺口（用户视角的阻塞点）

## 缺口 1：角色表要手写 JSON —— GUI零入口

**问题**：CLI 支持 `--role-map`，但 `votex-gui` 中 `grep RoleVoiceMap` 结果为**零命中**。
用户拿到一本 1083 章的小说，要让女儿角色用童声，必须：

1. 读完书统计出所有说话人（100+ 个）
2. 手工编写 JSON
3. 用命令行执行

`role::detect_speaker_from_context` 的输出**没有任何可视化出口**。这是最硬的阻塞。

**竞品对照**：Readify、Ghostreader 的多角色配音核心交互都是「左侧角色列表 → 勾选 → 试听 → 保存」，
而不是让用户写配置文件。Edify 的「Narrator AI Studio」同理。

## 缺口 2：成本不可见，试错代价高

一本网络小说约 50~100 万字，按Qwen3-TTS 约 300~600 字/秒、CPU 降速 3~5倍估算，
全本合成需要 **5~20 小时**。用户面对的问题是：

- 不知道跑完要多久
- 音色选错了要等几小时才发现
- 中途发现断句/音色有问题，只能从头重跑

**竞品对照**：所有成熟产品都提供「先出前 3 章样片，确认音色后再全本」的强制流程。

## 缺口 3：产物缺章节元数据，分发链路断

`WavWriter::write_concat` 输出**单一平坦音频流**，无章节表。
后果：

- 播放器里1077 段全挤在一起，无法跳章
- 无法产出标准m4b / Audible 格式
- 喜马拉雅/蜻蜓 FM 上传要求每章独立文件

**竞品对照**：ebook2audiobook 输出 m4b 带章节标记，是其核心竞争力之一（见文档 18 借鉴点 4）。

# 四、模块一：角色自动提取（核心增量）

## 4.0 实施记录（2026-10-06，S1+S2 已落地）

**代码**：`votex-domain/src/tts/role.rs` 新增 `RoleCandidate` / `extract_role_candidates` /
`build_role_map` / `RoleAssignments`；`tts/value_object.rs` 新增 `VoiceGender` / `VoiceLocale` /
`VoiceMeta`。均为**纯新增**，既有 `split_dialogue` / `detect_speaker_from_context` /
`resolve_voice` 签名与行为保持不变（仅 `trailing_name` 内部修正，见下）。

**测试**：domain 新增 20 个单测（`tts::role` 31 passed）；`e2e_novel_parse.rs` 新增 4 个
真实 GBK 全本 E2E（8 passed）。

### 真实数据推翻的两处方案假设

⚠️ **假设 1：「音色池有童声」—— 不成立**

| 实测 | 数量 |
|---|---|
| `zf_` 中文女声 | 55 |
| `zm_` 中文男声 | 45 |
| `af_`/`am_`/`bf_`/`bm_` 英文 | 3 |
| `xf_` **童声** | **0** |
| 中性音色 | 0 |

`xf_child` 仅存在于测试构造，真实 Kokoro 模型无童声音色。童声需靠 IndexTTS-2.5
零样本克隆提供，不能靠选音色池解决。→ §4.3 三级策略里「按性别分池取首个」对童声无效。

⚠️ **假设 2：「无中性音色时落兜底即可」—— 会导致 29006 段丢音色**

原方案 §4.3 策略 3 是「落 `dialogue_default`」，而 `dialogue_default` 缺省取
`VoiceGender::Neutral` 的首个音色。真实池**无中性音色** → `None` →
全部台词段（实测 29006 段）拿不到音色。
已改为逐级回退：`中性 → 男声 → 任意`，宁可中文男声也不留空。

⚠️ **附带缺陷（已修）**：按性别筛选时英文音色（`af_`…）字典序排在 `zf_`/`zm_` 之前
（'a' < 'z'），导致中文小说旁白被分到 `af_maple`（英文女声）。
已新增 `VoiceLocale` 并改为「性别 + 语种」二维选音（`pick_for_chinese`）。

### 真实书稿暴露的说话人噪声（已修，属既有缺陷）

《奶爸大文豪》全本首轮E2E 的 Top5 是 `张重(682) / 笑着(190) / 张重笑着(133) /
许雨涵(96) / 笑呵呵地(79)` —— **4/5 是噪声**。根因与修复：

| 噪声形态 | 根因 | 修复 |
|---|---|---|
| `张重笑着` | `X笑着说道` 中「笑着」被 4 字上限连人名一起吞 | `MODIFIER_TAIL_CUT`在助词处截断 |
| `张重笑` | 截断在「着」上，前一字已是动词 | `VERB_TAIL_NOISE` 剥离残留动词字 |
| `笑着` / `悄悄` / `慢慢` | 长度合法的纯副词，绕得过长度保护 | `ADVERB_ONLY_WORDS` 整串黑名单 |
| `李经理赶忙` | 副词被 4 字上限吞| `NAME_TAIL_NOISE_WORDS` 双字副词先剥离 |
| `张重又` | 粘连单字副词 | `NAME_TAIL_NOISE` 单字剥离 |
| `第三章` | 章节编号 | `looks_like_chapter_marker`，复用 `chapter::CHAPTER_UNITS` |

**修复后 Top5**：`张重(982) / 许雨涵(124) / 芃芃(88) / 胡慧芳(87) / 庄语(75)`，
全部为真实角色名。**性能 0.74s**（4.9MB GBK 全本，方案 §8.1 预算 2s）。

### 能力边界（明确记录，避免后续误解）

- **性别只能靠称谓确认**。无称谓线索的角色（叠字名「芃芃」、单字名）`gender`
  恒为 `Neutral`；`suggested_gender` 只是频次弱先验的**推测值**，
  **不参与 `build_role_map` 自动分配**（猜错性别会让全书配音越听越违和）。
  GUI 应显示「待确认」并让用户试听指定。
- `MODIFIER_TAIL_CUT` 含 `了`，故`李了了` 类人名会被削——网文场景下
  「…了了」作人名极罕见，取舍合理。
- 规则仍不覆盖无引号的间接引语（走 `dialogue_default`兜底）。

## 4.1 设计原则

**纯规则优先，LLM 兜底**。理由：
- 全书 100 万字若逐章送 LLM，成本不可接受
- 规则方案零延迟、零成本、可离线（符合项目离线约束）
- 仅当规则方案说话人数量失控（如 > 30 个）时，才提示用户"建议 LLM 辅助"

## 4.2 规则算法（复用现有能力，零新模型）

```rust
// votex-domain/src/tts/role.rs（已落地，签名与草图略有调整）

/// 角色候选及其证据
pub struct RoleCandidate {
    pub name: String,
    pub mentions: usize,                  // 置信度代理指标
    pub gender: VoiceGender,              // 有称谓证据的结论；Neutral = 未识别
    pub suggested_gender: Option<VoiceGender>, // 频次弱先验推测，**不参与分配**
    pub first_chapter: Option<usize>,     // 便于用户定位核对
    pub sample_line: Option<String>,      // 该角色首段真实台词，供 GUI 试听
}

impl RoleCandidate {
    pub fn gender_confirmed(&self) -> bool;
}

/// 全书扫描，汇总角色候选（按频次降序）
pub fn extract_role_candidates(text: &str, top_n: usize) -> Vec<RoleCandidate>;
pub fn extract_role_candidates_with(
    text: &str, top_n: usize, suggest_top_n: usize,
) -> Vec<RoleCandidate>;

/// 分配输入（避免用不可见字符串键承载保留角色——见实现说明）
pub struct RoleAssignments {
    pub roles: BTreeMap<String, String>,
    pub narrator: Option<String>,
    pub dialogue_default: Option<String>,
}

/// 按性别+语种自动分配 → RoleVoiceMap
pub fn build_role_map(
    candidates: &[RoleCandidate],
    voices: &[VoiceMeta],
    assignments: &RoleAssignments,
) -> RoleVoiceMap;
```

> **实现偏差说明**：原草图用 `assignments: &BTreeMap<String, String>` 承载
> 全部指定项，其中靠 `"\u{0}fallback"` 之类的**不可见字符串键**传旁白/兜底。
> 实现时改为独立的 `RoleAssignments` 结构体——用不可见字符串做 API 契约
> 后续维护者极易踩坑，且无法被类型系统检查。

**实现要点**：
1.复用 `split_dialogue` + `detect_speaker_from_context` 逐段扫描，
   累加 `speaker` 出现次数（**不改动现有函数签名，纯新增**）
2. 过滤噪声：长度 > 8 字符、纯数字、含标点的"说话人"直接丢弃
3. 性别启发（覆盖网文 80%场景）：
   - 称谓命中：`姑娘/小姐/女儿/妈妈/阿姨/奶奶/姐姐/妹妹/美女/夫人` → 女声候选
   - `先生/少爷/大叔/爷爷/父亲/爸爸/哥哥/弟弟/爷爷/师傅` → 男声候选
   - 出现频次 Top 3 且无明确称谓 → 默认旁白同性别（避免全部同音）
4. 按 `mentions` 降序返回，**截断Top N（N 可配，默认 20）**

**性能**：1083 章全本扫描为纯字符串操作，实测目标 < 2s（需在 E2E 中断言）。

## 4.3 音色分配策略

用户不必为每个角色手动选音色。三级策略：

| 优先级 | 策略 | 说明 |
|---|---|---|
| 1 | 用户显式指定 | GUI 里手动分配，最高优先（`RoleAssignments.roles`） |
| 2 | 性别+语种自动匹配 | `pick_for_chinese`：中文该性别 → 英文该性别 → 无约定语种 |
| 3 | `dialogue_default` 兜底 | 逐级回退 `中性 → 男声 → 任意`，**不留空** |

⚠️ **实测修正**：策略 2 的「按性别分池取首个」必须**同时按语种筛选**。
真实池里英文音色字典序在中文之前，只按性别筛选会给中文小说分到英文音色
（实测 `narrator=af_maple`）。已由 `VoiceLocale` + `pick_for_chinese`修正。

⚠️ **童声不可通过选池解决**：真实音色池无童声（见 §4.0）。童声角色只能由用户
在GUI 中指定克隆音色，或走 IndexTTS-2.5 零样本克隆。

## 4.4 前置改造：音色元数据（已落地）

原方案设想「音色是裸 ID 字符串，靠 `zf_`/`zm_`/`xf_` 前缀猜性别」。实现时发现
**该前缀体系比预期更广**，且被**三处重复硬编码**：

| 前缀 | 语种 | 性别 | 实测数量 |
|---|---|---|---|
| `zf_` | 中文 | 女 | 55 |
| `zm_` | 中文 | 男 | 45 |
| `xf_` | 中文 | 童 | 0 |
| `af_`/`bf_` | 英文 | 女 | 3 |
| `am_`/`bm_` | 英文 | 男 | — |

重复点：Kokoro `list_voices`（`kokoro.rs:510`）、GUI `tts_page.rs:104-114` 硬编码下拉。
已收口为 `VoiceGender::from_voice_id` / `VoiceLocale::from_voice_id` 单一实现
（`tts/value_object.rs`），新增引擎时只需改这一处。


## 5.2 交互要点（对标竞品核心）

1. **试听用样片而非全文**：音色试听取该角色的**首段真实台词**（如芃芃第一次叫"爸爸"
   那一段），而不是通用 TTS 试听句——真实上下文才能听出音色是否贴角色
2. **候选项批量勾选 + 批量赋音色**：网文常有 20+ 角色，逐个选是灾难
3. **保存为项目文件**：`role_map.json` 存项目目录，重复合成复用
4. **多引擎音色池分组显示**：TTS 主目录/IndexTTS 粤语音色混排时分组，避免选错

## 6.2 试制接口

复用已有 session 机制，只需包一层：

```rust
// votex-app/src/use_case/tts_use_case.rs 扩展
pub struct PreviewPlan {
    pub text: String,              // 前 N 章拼接文本
```

`estimate_synthesis_time` 需维护一张**引擎吞吐率表**（字/秒），可从

```yaml
tts:

    qwen3_tts: 320     # 字/秒，实测校正值
    index_tts2: 260
    kokoro: 900
```

## 7.2 章节边界实现

`build_synthesis_plan` 已标记 `is_new_chapter` 段（E2E 断言 1077 个）。
章节边界的落地只需在**流式拼接**时按该标记切分文件，而非改动领域层逻辑。

```rust
// votex-infra/src/audio/wav.rs 新增
/// 按章节标记流式切分写出，返回每章时长
pub fn write_by_chapters<...>(plan: &[SynthesisSegment], out_dir: &Path)
    -> Result<Vec<ChapterAudio>, AudioError>;
```

**顺带修复文档 18 记录的 P1-13**：`Flac`/`M4a` 是假格式（PCM 数据改扩展名），
方案：M4A 用 ffmpeg 转封装（`-c:a aac`），FLAC 或直接移除该枚举值。
**且 ffmpeg 路径硬编码 `C:\Apps\ffmpeg\bin\ffmpeg.exe`（`mp3.rs:17`）必须先改为
配置项 + 自动探测**，否则用户机器上没有该路径即全线MP3 导出失败。

## 7.3 m4b 输出（阶段二）

依赖 ffmpeg 元数据写入：

```bash
ffmpeg -i 001.mp3 -i 002.mp3 -f concat -safe 0 -i list.txt \
  -metadata title="书名" -metadata artist="作者" \
  -c:a aac -f mp4 output.m4b
```

同时写 `chapters.txt`（ffmetadata 格式）挂载章节。

- `suggested_gender` 只能作提示，**S4 的 GUI 必须让用户试听确认**，
  不能假装规则能定性别；
- 自动分配的正确目标不是「性别正确」，而是**「声线可分辨」**——
  男女交错 + 跳号是当前规则下能达到的最优解；
- 若书稿本身大量使用「爸爸」「爷爷」这类称谓（口语对话体），
  性别启发才有效。规则的价值依文风而异，需在S4 界面如实告知用户。

# 九、风险与取舍

| 风险 | 等级 | 对策 |
|---|---|---|
| 说话人识别仅覆盖"XX说：『…』"，无引号的间接引语会漏 | 中 | 已在 E2E 记录基线（台词段 > 1 万）；漏检走 `dialogue_default`，可接受 |
| 女声音色池不足（男多女少）导致多角色同音 | 中 | S1 元数据补齐后按性别分池；不足时提示用户扩展音色 |
| ffmpeg 依赖与单二进制分发冲突 | **高** | 文档 18 已明确定调：不做内置 ffmpeg。**分章 mp3 优先用纯 Rust 实现**，
ffmpeg 仅作可选加速路径，缺失时降级而非报错 |
| 20+ 角色时 GUI 列表过长 | 低 | 默认折叠「次要角色」，按出现频次排序，支持搜索 |
| LLM 兜底方案引入云依赖，违反离线约束 | 中 | 默认关闭；开启需用户在配置中显式声明 API Key |
