## 架构设计

基于 DDD 分层架构，定义 votex 的模块结构、依赖关系、Provider 抽象和关键技术决策。



### 1. 分层架构总览

```
┌──────────────────────────────────────────────────────────┐
│                      表现层 Presentation                  │
│  ┌────────────────────┐  ┌────────────────────────────┐  │
│  │    CLI (clap)       │  │    GUI (egui/eframe)       │  │
│  └────────┬───────────┘  └────────────┬───────────────┘  │
├───────────┼───────────────────────────┼──────────────────┤
│           │       应用层 Application   │                  │
│  ┌────────┴───────────────────────────┴───────────────┐  │
│  │              用例编排（Use Cases）                    │  │
│  │  TtsUseCase / AsrUseCase / OcrUseCase / ModelUseCase /           │  │
│  │  PipelineUseCase / ConfigUseCase / TaskUseCase      │  │
│  └────────────────────────┬───────────────────────────┘  │
├───────────────────────────┼──────────────────────────────┤
│                           │       领域层 Domain           │
│  ┌────────────────────────┴───────────────────────────┐  │
│  │  实体 / 值对象 / 领域服务 / 仓储接口（trait）         │  │
│  │  Model / TtsTask / AsrTask / OcrTask / Pipeline / AppConfig  │  │
│  │  TtsProvider(trait) / AsrProvider(trait) / OcrProvider(trait)│  │
│  └────────────────────────┬───────────────────────────┘  │
├───────────────────────────┼──────────────────────────────┤
│                           │     基础设施层 Infrastructure  │
│  ┌────────────────────────┴───────────────────────────┐  │
│  │  Provider 实现 / 仓储实现 / 文件 I/O / 外部库封装     │  │
│  │  KokoroProvider / IndexTts2Provider /               │  │
│  │  WhisperProvider / PaddleOcrProvider /              │  │
│  │  OnnxRuntime / GgmlEngine / FfmpegBridge            │  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

**依赖规则**：上层依赖下层，下层不依赖上层。领域层不依赖任何外部库，仅定义 trait 接口。



### 2. Crate 结构

采用 Rust workspace 多 crate 结构，实现分层隔离：

```
votex/
├── Cargo.toml                  # workspace 根
├── crates/
│   ├── votex-domain/           # 领域层：实体、值对象、领域服务、trait
│   ├── votex-app/              # 应用层：用例编排，依赖 votex-domain
│   ├── votex-infra/            # 基础设施层：Provider 实现、仓储实现
│   ├── votex-cli/              # 表现层：CLI 入口
│   └── votex-gui/              # 表现层：GUI 入口
├── models/                     # 模型文件目录（运行时）
├── docs/                       # 项目文档
└── src/
    └── main.rs                 # 二进制入口，根据参数启动 CLI 或 GUI
```

#### 2.1 Crate 依赖关系

```
votex-cli ──→ votex-app ──→ votex-domain ←── votex-infra
votex-gui ──→ votex-app ──→ votex-domain ←── votex-infra
                                  ↑
                            (trait 定义在此)
```

| Crate | 依赖 | 说明 |
|-------|------|------|
| `votex-domain` | 无外部依赖 | 纯领域逻辑，定义 trait 和实体 |
| `votex-app` | `votex-domain` | 用例编排，通过 trait 调用领域服务 |
| `votex-infra` | `votex-domain` + 外部库 | 实现领域层定义的 trait |
| `votex-cli` | `votex-app` + `votex-infra` + `clap` | CLI 入口，组装依赖 |
| `votex-gui` | `votex-app` + `votex-infra` + `egui` | GUI 入口，组装依赖 |

#### 2.2 依赖注入

应用启动时在 `main.rs` 中完成依赖组装：

```rust
// 伪代码：依赖注入（实际代码见 crates/votex-cli/src/main.rs）
fn main() {
    let db_path = Path::new("data/votex.db");

    // SQLite 仓储（共享同一数据库文件）
    let tts_task_repo = SqliteTtsTaskRepository::open(db_path);
    let asr_task_repo = SqliteAsrTaskRepository::open(db_path);
    let ocr_repo = SqliteOcrTaskRepository::open(db_path);
    let pipeline_repo = SqlitePipelineRepository::open(db_path);
    let download_repo = SqliteDownloadRepository::open(db_path);

    // 使用用例（可选传入仓储）
    let mut ocr_use_case = OcrUseCase::new();
    ocr_use_case = ocr_use_case.with_repo(Arc::new(ocr_repo));

    let pipeline_use_case = PipelineUseCase::new()
        .with_repo(Arc::new(pipeline_repo));

    // TTS/ASR 用例如需持久化，可注入 TtsTaskRepository / AsrTaskRepository
    let tts_use_case = TtsUseCase::new();
    let asr_use_case = AsrUseCase::new();

    // 启动表现层
    if args.gui { run_gui(...); }
    else { run_cli(...); }
}
```

#### 3.2 Provider 抽象

**TtsProvider trait**

```rust
pub trait TtsProvider: Send + Sync {
    /// 返回引擎类型
    fn engine_kind(&self) -> EngineKind;

    /// 加载模型到内存
    fn load(&mut self, model: &Model) -> Result<()>;

    /// 释放模型资源
    fn unload(&mut self) -> Result<()>;

    /// 合成单段语音
    fn synthesize(
        &self,
        text: &str,
        voice: &VoiceId,
        params: &TtsParams,
    ) -> Result<AudioData>;

    /// 列出可用音色
    fn list_voices(&self) -> Vec<VoiceId>;

    /// 输出采样率
    fn sample_rate(&self) -> u32;

    /// 是否已加载
    fn is_loaded(&self) -> bool;
}
```

**AsrProvider trait**

```rust
pub trait AsrProvider: Send + Sync {
    /// 返回引擎类型
    fn engine_kind(&self) -> EngineKind;

    /// 加载模型到内存
    fn load(&mut self, model: &Model) -> Result<()>;

    /// 释放模型资源
    fn unload(&mut self) -> Result<()>;

    /// 识别单段音频
    fn recognize(
        &self,
        audio: &AudioData,
        params: &AsrParams,
    ) -> Result<RecognizeOutput>;

    /// 期望输入采样率
    fn sample_rate(&self) -> u32;

    /// 是否已加载
    fn is_loaded(&self) -> bool;
}
```

**扩展性**：后续版本新增引擎或在线 API 时，只需实现对应 trait 并注册到 Provider 容器中，无需修改领域层和应用层代码。

#### 4.2 用例编排示例

**TtsUseCase** 编排流程：

```
1. 验证输入（文件存在、参数合法）
2. 加载 TTS 模型（若未加载）
3. 文本预处理 + 分段
4. 逐段合成（调用 TtsProvider）
5. 音频拼接（调用 AudioConcatenator）
6. 导出文件
7. 渐进式质量提示（若开启）
8. 更新任务状态
```

**PipelineUseCase** 编排流程：

```
1. 根据 PipelineKind 构建阶段列表
2. 逐阶段执行，阶段间传递中间产物
3. 任一阶段失败 → 暂停，等待用户操作
4. 全部完成 → 渐进式质量提示
```

#### 5.3 下载器设计

**多源下载策略**

```
MirrorResolver
  ├── resolve(entry, priority) → Vec<DownloadFile>  // 按优先级返回 URL 列表
  │
Downloader
  ├── download(urls: Vec<Url>, dest: &Path) → Result<()>
  │   ├── 尝试第一个 URL
  │   ├── 失败 → 尝试下一个 URL
  │   ├── 支持 HTTP Range 断点续传
  │   └── 全部失败 → 返回错误
  │
SqliteDownloadRepository  ← 下载进度回调写入
  ├── 初始状态 Pending
  ├── 开始下载 → Downloading（记录已下载字节数）
  ├── 进度更新 → update_progress()（每 1MB 或完成时）
  ├── 完成 → Completed
  └── 启动时 find_incomplete() → 恢复未完成的下载
```

#### 6.3 异步任务执行

TTS/ASR 推理为 CPU 密集型，在独立线程中执行：

```
┌─────────────┐     命令/请求      ┌──────────────┐
│  GUI/CLI     │ ──────────────────→ │  任务线程      │
│  (主线程)    │ ←────────────────── │  (推理执行)    │
│              │     进度/结果       │              │
└─────────────┘                     └──────────────┘
```

- 主线程负责 UI 渲染和用户交互
- 任务线程执行推理，通过 channel 发送进度和结果
- 同一时刻仅 1 个 TTS 任务 + 1 个 ASR 任务执行（避免内存峰值叠加）



### 7. 错误处理策略

#### 7.1 错误类型层次

```rust
// 领域层错误
enum DomainError {
    Model(ModelError),
    Tts(TtsError),
    Asr(AsrError),
    Ocr(OcrError),
    Pipeline(PipelineError),
    Config(ConfigError),
}

// 各子错误类型映射到错误码
impl DomainError {
    fn error_code(&self) -> &str {
        match self {
            DomainError::Model(e) => e.code(),    // VM001 ~ VM010
            DomainError::Tts(e) => e.code(),      // VT001 ~ VT011
            DomainError::Asr(e) => e.code(),      // VA001 ~ VA007
            DomainError::Ocr(e) => e.code(),      // VO001 ~ VO007
            DomainError::Config(e) => e.code(),   // VC001 ~ VC004
            DomainError::Pipeline(e) => e.code(), // VP001 ~ VP005
        }
    }
}
```

#### 7.2 错误传播

```
基础设施层 → Result<T, InfraError>
    ↓ 转换
领域层 → Result<T, DomainError>
    ↓ 转换
应用层 → Result<T, AppError>（附带用户提示文案）
    ↓ 转换
表现层 → CLI: stderr 输出 / GUI: 提示对话框
```

- 领域层和基础设施层使用 `thiserror` 定义错误类型
- 应用层将技术错误转换为用户友好的中文提示
- 表现层根据错误类型选择展示方式（Toast/Dialog/Inline）



### 8. 关键技术决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 异步运行时 | 不使用 async runtime | 推理为 CPU 密集型，使用线程池而非 async；下载使用独立线程 + 阻塞 HTTP |
| 线程管理 | `std::thread` + `crossbeam-channel` | 简单可靠，避免引入 tokio 的复杂性 |
| GUI 框架 | egui + eframe | 即时模式，适合工具类应用，单二进制分发友好 |
| ONNX 推理 | ort（ONNX Runtime Rust 绑定） | 成熟稳定，CPU 推理性能好 |
| ASR 推理（Whisper/SenseVoice） | sherpa-onnx | 统一 ASR 推理框架，ONNX 格式支持，多引擎封装 |
| ASR 推理（Paraformer/Qwen3-ASR） | ort（ONNX Runtime Rust 绑定） | 直接 ONNX Runtime 调用，低延迟 |
| 音频处理 | ffmpeg-next | 功能全面，支持多格式编解码 |
