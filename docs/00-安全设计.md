## 一、威胁模型与设计原则

### 1.1 项目特征

votex（声阅）是**离线优先**的桌面语音工具：

- 文本处理、模型推理全部本地完成（TTS / ASR / OCR / 翻译）
- 唯一出网行为是「下载模型」与「调用用户主动配置的云 API」
- 单二进制分发，无服务端，无账号体系

### 1.2 资产清单

| 资产 | 存放位置 | 敏感级别 |
| :--- | :--- | :-- |
| 云服务 API Key | 配置文件 / 环境变量 | 高 |
| AES 主密钥 | 工作区根 `.key` | 高（泄露即全部密文失效） |
| 用户文本 / 音频 | 本地临时文件、SQLite | 中（隐私内容） |
| 模型文件 | `models/` | 中（版权 + 完整性） |

### 1.3 设计原则

1. **本地优先，不上传**：用户文本默认不出网。任何出网路径必须是用户显式配置云服务后才会触发。
2. **不静默降级**：密钥缺失、校验失败、配置解析失败一律显式报错，禁止兜底默认值。
3. **落盘即视为泄露**：日志与错误消息在写入前统一脱敏。
4. **完整性优先于可用性**：下载文件必须经 SHA256 校验后才落到最终路径。
5. **失败可恢复**：任何破坏性操作（删除模型、覆盖配置）必须二次确认或先备份。

## 二、密钥管理

### 2.1 主密钥

**实现位置**：`crates/votex-infra/src/security/crypto.rs`

| 项目 | 取值 | 说明 |
| :--- | :--- | :-- |
| 算法 | AES-256-GCM | 带认证标签，可检测篡改 |
| 密钥长度 | 32 字节 | `KEY_SIZE = 32` |
| 密钥来源 | `OsRng`（操作系统 CSPRNG） | 首次启动生成 |
| 密钥文件 | 工作区根 `.key` | 二进制裸存储 |
| Nonce | 12 字节，每次加密新生成 | GCM 安全性前提，**绝不可复用** |
| 存储格式 | `ENC(base64(nonce ‖ ciphertext‖ tag))` | 便于识别已加密字段 |
| 文件权限 | Unix `0o600`；Windows `icacls` 仅当前用户 | 见 `restrict_key_permissions()` |

**路径解析**：`.key` 位于 `WorkspacePaths::workspace_root()`，**不使用进程当前目录**。
GUI 双击启动时 cwd 可能是任意目录，若按 cwd 定位会导致每次启动都「找不到密钥 → 重新生成」，
旧密钥加密的配置全部无法解密。解析顺序：

1. 环境变量 `VOTEX_WORKSPACE_DIR`
2. `application.yml` 所在目录
3. 可执行文件所在目录
4. 当前目录及其父目录（`cargo run` / `cargo test`）

### 2.2 密钥保护

- **禁止提交到版本库**：`.key` 已在 `.gitignore` 中
- **禁止硬编码兜底密钥**：密钥异常时 `initialize()` 返回 `Err`，**不提供默认值**
- **密钥长度强校验**：长度不等于 32 字节直接报 `InvalidKeyLength`，不截断、不补齐
- **权限收紧失败不阻断启动**（Windows）：记 warn 让用户知情，因 Windows 用户目录 ACL 已提供基础保护

### 2.3 云服务凭证

**实现位置**：`crates/votex-infra/src/api/base.rs`

读取优先级：`显式参数` → `环境变量` → 配置文件密文

支持的环境变量：

| 变量 | 用途 |
| :--- | :--- |
| `DEEPSEEK_API_KEY` | LLM 文案生成 / 术语翻译 |
| `ALIYUN_ACCESS_KEY_ID` | 阿里云 ASR |
| `ALIYUN_ACCESS_KEY_SECRET` | 阿里云 ASR |
| `ALIYUN_APP_KEY` | 阿里云 ASR 应用标识 |
| `AZURE_SPEECH_KEY` | Azure ASR |
| `AZURE_SPEECH_REGION` | Azure ASR 区域 |
| `FFMPEG_PATH` | ffmpeg 可执行文件路径 |

**约束**：

- 密钥**不得**出现在 `tracing::info!` / `debug!` 中，须经脱敏器处理（见第三章）
- 密钥**不得**写入 SQLite；数据库只存业务数据
- 云服务为**可选**功能，未配置时对应功能应给出明确提示而非静默失败

## 三、日志脱敏

**实现位置**：`crates/votex-infra/src/logging/desensitizer.rs`
**接入点**：`crates/votex-infra/src/logging/init.rs:95` 与 `:182`（所有日志写入前）

### 3.1 覆盖范围

| 类别 | 规则 | 示例 |
| :--- | :--- | :-- |
| 手机号 | 11 位 + 可选国家码 | `13812345678` → `138****5678` |
| 身份证 | 18 位（含校验位） | `110101199001011234` → `110101******1234` |
| 身份证 | 15 位（历史遗留） | `110101900101123` → `110101******` |
| 邮箱 | 标准格式 | `user@example.com` → `u***@example.com` |
| IPv4 | 逐段校验 0-255 + 边界判定 | `192.168.1.1` → `192.168.*.*` |
| API Key | `sk-` / `xox[bps]-` / `AKID` / `eyJ`(JWT) / `ghp_` / `gho_` | `sk-abc…` → `sk-***` |
| 云凭证 | `LTAI`（阿里云 STS）/ `ASIA`（AWS STS） | `LTAI5t…` → `LTA***` |
| 凭据赋值 | `key=value` / `key: value` / `"key": "value"` | `DEEPSEEK_API_KEY=xxx` → `…=***` |
| 裸长串 | ≥24 位 base64 字符集 | 阿里云 AccessKeySecret → `***` |

### 3.2 两条关键设计决策

**决策一：不使用 `\b` 词边界**

Rust `regex` 的 `\b` 基于 ASCII `\w`（字母数字下划线）。中文日志里
「身份证号110101199001011234」中汉字与数字之间**不存在词边界**，
加了 `\b` 反而完全匹配不到 —— 这是 1.0 版实现的真实漏脱敏缺陷。
现全部改为「形状匹配 + 闭包内边界判定」。

**决策二：计量类键名显式放行**

`token_count=128`、`max_token_len`、`batch_size` 这类统计量若一并抹掉会显著降低日志可诊断性。
`is_counting_key()` 按后缀白名单（`count`/`len`/`num`/`size`/`max`/`min`/`total`/`index`）放行。

### 3.3 优先级：宁可多脱敏，不可漏脱敏

日志一旦落盘即视为已泄露，无法撤回。因此规则顺序为：

1. 凭据赋值（`KEY=xxx`）—— 最精确，优先处理
2. 带前缀的密钥
3. 身份证 → 手机号 → IP → 邮箱
4. 裸长串兜底

新增规则时**必须同时补单测**，`desensitizer.rs` 现有 17 个用例。

### 3.4 已知限制

- 规则基于**正则 + 字符集启发式**，无法识别任意格式的自定义密钥
- 若用户把密钥写进自己的文本内容再由程序处理，脱敏器只能覆盖前述已知形态
- 因此**优先推荐环境变量**注入密钥，而非写入被处理的文本

## 四、模型下载完整性

**实现位置**：`crates/votex-infra/src/download/downloader.rs`

### 4.1 下载流程

```
解析镜像 URL（按 priority 顺序）
  → 复用已有文件（大小匹配则跳过）
  → 下载到 <目标>.part 临时文件
  → 校验大小
  → 校验 SHA256          ← 校验失败即视为失败，删除临时文件
  → rename 到最终路径
  → 清理 .etag 元数据
```

### 4.2 三条硬性约束

1. **强制 HTTPS**：`Client::builder().https_only(true)`，不接受明文下载
2. **临时文件 + rename**：中断只会留下 `.part`，不会产生「看似完整」的残片
3. **SHA256 校验错误即失败**：旧实现中 `Err(e) => warn!` 后 fall-through 进「下载成功」分支，
   等于校验可被任意 IO 错误绕过 —— 此路径已封死

### 4.3 断点续传

- 仅在 `models.download.resume: true` 时启用
- 续传携带 `If-Range: <ETag>`，服务端内容已变化时自动从头重下，
  避免把新内容的尾部续接到旧内容之后产生**静默损坏**的文件
- ETag 元数据存于 `<目标>.part.etag`

### 4.4 超时

| 项 | 值 | 来源 |
| :--- | :--- | :-- |
| 连接超时 | 30 秒 | 常量 `CONNECT_TIMEOUT_SECS` |
| 单次下载总超时 | `models.download.timeout` | 配置文件（默认 300 秒，0 时回退 3600） |

**为什么需要连接超时**：TCP 连接阶段无响应时 `read_timeout` 尚未生效，
只能靠 `connect_timeout` 中断，否则下载线程会永久挂起。

### 4.5 已知缺口

**165 个模型文件条目中绝大多数没有 sha256 值**。这意味着：

- 校验链路本身正确（失败即失败）
- 但清单里没写期望值时，实际处于「只校验可下载性、不校验内容」状态
- 供应链攻击面**尚未完全关闭**

补齐 sha256 需要逐个下载官方文件计算，属于待办项。

## 五、本地数据隐私

### 5.1 数据流向

| 数据 | 是否出网 | 条件 |
| :--- | :--- | :-- |
| 待合成 / 转写的文本 | **否** | 默认全部本地处理 |
| 音频文件 | **否** | 本地 ONNX 推理 |
| OCR 图片 | **否** | PaddleOCR 本地推理 |
| 翻译原文 | **否** | NLLB / HY-MT 本地推理 |
| 翻译原文 | 是 | **仅当用户配置了云翻译引擎**（DeepSeek / 阿里云） |
| 文案生成提示 | 是 | **仅当配置了 `DEEPSEEK_API_KEY`** |

**结论**：AGENTS.md 要求的「用户文本内容不上传网络，本地处理全流程」在
**未配置云服务时严格成立**；配置云服务后，仅对应功能会出网，且由用户主动触发。

### 5.2 禁止的行为

- ❌ 在未配置云服务时把文本发到任何网络端点
- ❌ 把密钥写进 SQLite
- ❌ 把密钥写进日志（未经脱敏）
- ❌ 把用户文本写入临时文件后不清理
- ❌ 静默上传崩溃报告 / 使用统计

## 六、文件与命令安全

### 6.1 路径穿越防护

用户可控的路径（音色名、模型名、输出目录）必须做规范化校验。

**现有防护**：`crates/votex-infra/src/tts/voice_library.rs` 的 `音色名_路径穿越拒绝` 用例，
拒绝含 `..` 与路径分隔符的音色名。

**注意**：解压第三方压缩包时必须防 zip slip —— 见 `download/archive.rs` 的
`拒绝路径穿越` 用例（校验条目路径不含 `..` 且不绝对）。

### 6.2 子进程调用

`ffmpeg` 通过 `Command` 调用：

- 路径来自环境变量 `FFMPEG_PATH` 或默认 `ffmpeg`，**不由用户输入拼接**
- 音频文件路径作为独立参数传入，不拼进 shell 字符串
- 未使用 `sh -c`，避免 shell 注入

### 6.3 删除操作

- **模型删除**：GUI 必须二次确认（`settings_page.rs` 的删除确认弹窗），
  显示路径与体积，失败必须提示 —— 对应 AGENTS.md「禁止自动删除模型文件」
- **配置覆盖**：GUI 保存配置改为基于已加载配置增量覆盖，
  不使用 `..Default::default()` 静默清空八段配置

## 七、加密格式规范

### 7.1 `ENC(...)` 标记

```
ENC( base64( nonce[12] ‖ ciphertext ‖ tag[16] ) )
```

- `is_encrypted()` 判据：能剥掉 `ENC(` / `)` 前缀后缀**且载荷非空**
- 空标记 `ENC()` 不是任何合法密文，判为未加密

### 7.2 空串处理

`encrypt("")` 走**完整加密流程**，不提前返回裸空串。

原因：调用方普遍用 `is_encrypted()` 判断字段是否已加密。
若 `encrypt("")` 返回 `""`，空值会被误判为明文而跳过解密，
造成「加密存了却读不回来」的不一致。

### 7.3 自动加解密

- 保存配置时：`is_encrypted(v)` 为假 → `encrypt(v)`
- 加载配置时：`is_encrypted(v)` 为真 → `decrypt(v)`
- 防循环加密：已加密的值不会被二次加密
