## 实施计划

基于 DDD + TDD 开发策略，将 votex v1 的实施分为 6 个阶段，每个阶段产出可验证的增量。



### 1. 阶段总览

```
阶段0: 项目骨架 ──→ 阶段1: 模型管理 ──→ 阶段2: TTS 核心 ──→ 阶段3: ASR 核心 ──→ 阶段4: 流水线与批量 ──→ 阶段5: GUI 与集成
```

| 阶段 | 名称 | 核心交付物 | 依赖 |
|------|------|-----------|------|
| 0 | 项目骨架 | Workspace 结构、领域层 trait、错误体系、日志框架 | 无 |
| 1 | 模型管理 | 模型下载/导入/校验/加载、CLI model 子命令 | 阶段 0 |
| 2 | TTS 核心 | Kokoro TTS 合成、文本分段、音频拼接导出、CLI tts 子命令 | 阶段 1 |
| 3 | ASR 核心 | Whisper 识别、音频切片、字幕生成导出、CLI asr 子命令 | 阶段 1 |
| 4 | 流水线与批量 | 流水线编排、批量任务、渐进式质量、任务队列 | 阶段 2 + 3 |
| 5 | GUI 与集成 | egui 界面、首次启动引导、端到端测试、打包分发 | 阶段 4 |

> 阶段 2 和阶段 3 可并行开发（均依赖阶段 1，互不依赖）。

### 3. 阶段 1：模型管理

### 8. TDD 策略

#### 8.1 测试金字塔

```
          ┌──────────┐
          │  E2E 测试  │   少量，覆盖核心流程
          │  (阶段5)   │
         ┌┴──────────┴┐
         │  集成测试     │   中等，覆盖模块交互
         │  (各阶段)    │
        ┌┴────────────┴┐
        │   单元测试      │   大量，覆盖领域逻辑
        │   (各阶段)     │
       └────────────────┘
```

#### 8.2 测试原则

1. **先写测试再写实现**：领域层的值对象、领域服务、状态流转必须先写测试
2. **领域层测试不依赖外部**：使用 Mock 仓储和 Mock Provider，不依赖真实模型文件
3. **基础设施层测试可依赖文件系统**：使用临时目录（`tempfile` crate），测试后清理
4. **集成测试使用小模型**：使用 Kokoro 最小测试模型和 Whisper tiny 模型
5. **CI 不运行推理测试**：推理测试标记为 `#[ignore]`，本地手动运行

#### 8.3 Mock 策略

```rust
// 领域层定义 trait，测试中使用 Mock
pub struct MockTtsProvider {
    voices: Vec<VoiceId>,
}

impl TtsProvider for MockTtsProvider {
    fn synthesize(&self, text: &str, voice: &VoiceId, _: &TtsParams) -> Result<AudioData> {
        // 返回固定长度的静音 PCM 数据
        Ok(AudioData::silence(self.sample_rate(), 1000))
    }
    // ...
}
```

#### 8.4 测试覆盖率目标

| 层 | 目标覆盖率 | 说明 |
|----|-----------|------|
| 领域层 | ≥ 90% | 核心业务逻辑，必须高覆盖 |
| 应用层 | ≥ 70% | 用例编排，依赖 Mock |
| 基础设施层 | ≥ 50% | 外部库封装，部分逻辑难以 Mock |
| 表现层 | ≥ 30% | GUI 测试成本高，重点测试状态管理 |



### 9. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| ONNX Runtime 编译复杂 | 阶段 2 阻塞 | 提前验证 ort crate 在 Windows 上的编译和链接 |
| egui 复杂布局限制 | 阶段 5 阻塞 | 阶段 0 提前做 egui 原型验证（SRT 编辑器） |
| Kokoro/IndexTTS2 ONNX 模型格式不确定 | 阶段 2 阻塞 | 阶段 1 期间下载模型并分析 ONNX 图结构 |
| Whisper ONNX 模型 sherpa-onnx 兼容性 | 阶段 3 阻塞 | 提前验证 sherpa-onnx 对不同 Whisper ONNX 版本的支持 |
| 内存峰值超标 | 性能不达标 | 阶段 2/3 分别做内存 Profiling，TTS/ASR 不同时执行 |
| ffmpeg 依赖分发 | 单二进制目标受影响 | 静态链接 ffmpeg 或使用 ffmpeg-sidecar 方案 |
