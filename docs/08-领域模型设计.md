## 领域模型设计

基于 DDD（领域驱动设计）思想，识别 votex 的核心领域、实体、值对象、聚合根、领域服务和仓储接口。



### 1. 领域划分

```
┌─────────────────────────────────────────────────┐
│                  votex 领域地图                    │
├─────────────┬───────────────┬───────────────────┤
│  模型管理域  │   语音合成域   │    语音识别域      │
│  Model      │   TTS         │    ASR            │
├─────────────┼───────────────┴───────────────────┤
│  图文识别域  │              任务编排域 Pipeline     │
│  OCR        │                                    │
├─────────────┴───────────────────────────────────┤
│              配置域 Config                        │
└─────────────────────────────────────────────────┘
```

| 领域 | 核心职责 | 聚合根 |
|------|---------|--------|
| 模型管理（Model） | 模型生命周期：下载、导入、校验、加载、释放 | Model |
| 语音合成（TTS） | 文本分段、语音合成、音频拼接、导出 | TtsTask |
| 语音识别（ASR） | 音频切片、语音识别、字幕生成、导出 | AsrTask |
| 图文识别（OCR） | 图片文字检测、方向分类、文字识别、结果导出 | OcrTask |
| 任务编排（Pipeline） | 多步骤流水线编排、阶段管理、渐进式质量 | Pipeline |
| 配置（Config） | 全局参数管理、配置读写 | — （无聚合根，纯值对象） |

**ModelId（值对象）**

| 字段 | 类型 | 说明 |
|------|------|------|
| key | String | 标识键，如 `kokoro-82m`、`whisper-base` |

#### 2.2 值对象

**ModelKind**

```
enum ModelKind { Tts, Asr, Ocr, Translation }
```

**EngineKind**

```
enum EngineKind { Kokoro, IndexTTS2, Whisper, PaddleOCR, EasyOcr }
```

**ModelStatus**

```
enum ModelStatus {
    NotDownloaded,    // 未下载
    Downloading(DownloadProgress),  // 下载中
    DownloadPaused,   // 下载暂停
    Verifying,        // 校验中
    VerifyFailed,     // 校验失败
    Ready,            // 已就绪
    Loading,          // 加载中
    Loaded,           // 已加载（可推理）
    LoadFailed(String), // 加载失败
}
```

**DownloadProgress**

| 字段 | 类型 | 说明 |
|------|------|------|
| downloaded_bytes | u64 | 已下载字节数 |
| total_bytes | u64 | 总字节数 |
| source_name | String | 当前下载源名称 |

**DownloadSource**

| 字段 | 类型 | 说明 |
|------|------|------|
| mirror | String | 镜像名称（如 "huggingface"、"modelscope"） |
| urls | Vec<Url> | 按优先级排列的下载 URL |

**ModelRegistryEntry**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 模型唯一标识（也是默认存储子目录名） |
| name | String | 显示名称 |
| kind | String | 模型类型：Tts / Asr / Ocr |
| engine | String | 引擎名：Kokoro / IndexTTS2 / Whisper / PaddleOCR 等 |
| sub_dir | Option\<String\> | 存储子目录覆盖（可选，覆盖 id） |
| tokenizer | Option\<TokenizerConfig\> | 分词器配置（可选，仅需特殊处理的模型需要声明） |
| files | Vec\<ModelFileEntry\> | 该模型所需下载的文件列表 |

**TokenizerConfig**

分词器配置，用于解决 HuggingFace tokenizer 与原始 SentencePiece 模型之间 ID 映射不一致的问题。

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| type | Option\<String\> | `"sentencepiece"` | 分词器类型，当前仅支持 `sentencepiece` |
| id_offset | i64 | `0` | 内容 token ID 偏移量。某些 HuggingFace tokenizer（如 NLLB）重排了特殊 token，导致原始 SentencePiece 的 ID 需要偏移后才能与 ONNX 模型对齐 |
| eos_on_input | bool | `false` | 编码器输入末尾是否自动追加 EOS token |
| decoder_start_token | Option\<String\> | `null` | 解码器起始 token，设为 `"eos"` 表示使用 EOS token |
| added_tokens | HashMap\<String, i64\> | `{}` | 语言代码等附加 token 的 ID 映射表 |

**应用场景：**

- **NLLB-200**：HuggingFace NllbTokenizer 将 `<unk>` 从 SP ID 0 重排到 HF ID 3，导致所有内容 token ID 偏移 +1（原始 SP ID 3 → HF ID 4，...，原始 SP ID 255999 → HF ID 256000）。语言代码作为 added_tokens 追加在词汇表末尾。配置：`id_offset: 1`
- **Opus-MT**：使用独立的 `source.spm` + `target.spm` + `vocab.json` 进行 ID 映射，无偏移问题，无需配置
- **M2M-100**：使用原始 SentencePiece ID 空间，通常无需偏移配置

> 框架通过 `SentencePieceBpe.encode_with_config()` 和 `decode_with_config()` 统一处理 ID 偏移，provider 只需从注册表 YAML 加载配置即可，无需在业务代码中处理偏移逻辑。

**ModelFileEntry**

| 字段 | 类型 | 说明 |
|------|------|------|
| name | String | 相对于模型子目录的路径（如 "kokoro-v1.0.int8.onnx"） |
| sha256 | Option\<String\> | 可选的 SHA256 校验值 |
| sources | HashMap\<String, String\> | 镜像源映射：镜像名 → 下载 URL |

**Hash**

| 字段 | 类型 | 说明 |
|------|------|------|
| algorithm | HashAlgorithm | 哈希算法（SHA256） |
| value | String | 哈希值 |

#### 2.3 领域服务

**ModelService**

| 方法 | 说明 |
|------|------|
| `download(model_id, mirror) -> Result<()>` | 下载模型（按镜像优先级尝试多源） |
| `import(model_id, path) -> Result<()>` | 从本地路径导入模型 |
| `verify(model_id) -> Result<()>` | 校验模型文件完整性 |
| `remove(model_id) -> Result<()>` | 删除模型 |
| `get_status(model_id) -> ModelStatus` | 查询模型状态 |
| `list(kind: Option<ModelKind>) -> Vec<Model>` | 列出模型 |

**ModelLoader**

| 方法 | 说明 |
|------|------|
| `load(model_id) -> Result<LoadedModel>` | 加载模型到内存 |
| `unload(model_id) -> Result<()>` | 释放模型资源 |
| `is_loaded(model_id) -> bool` | 检查模型是否已加载 |

#### 2.4 仓储接口

**ModelRepository**

| 方法 | 说明 |
|------|------|
| `find_by_id(id: &ModelId) -> Option<Model>` | 按 ID 查找模型 |
| `find_by_kind(kind: ModelKind) -> Vec<Model>` | 按类型查找模型 |
| `save(model: &Model) -> Result<()>` | 保存模型信息 |
| `delete(id: &ModelId) -> Result<()>` | 删除模型记录 |
| `exists(id: &ModelId) -> bool` | 模型是否存在 |

实现：`SqliteModelRepository`（SQLite `models` 表）+ `FileModelRepo`（内存 HashMap）

**DownloadRecord（下载记录，基础设施层）**

| 字段 | 类型 | 说明 |
|------|------|------|
| model_id | String | 所属模型 ID（如 "kokoro-82m"） |
| file_name | String | 文件名（如 "model.onnx"） |
| url | String | 下载源 URL |
| bytes_downloaded | u64 | 已下载字节数 |
| total_bytes | u64 | 文件总大小（0 表示未知） |
| status | String | Pending / Downloading / Paused / Completed / Failed |
| error_message | Option\<String\> | 错误信息 |
| created_at | String | 创建时间（Unix 时间戳） |
| updated_at | String | 更新时间 |

实现：`SqliteDownloadRepository`（SQLite `downloads` 表，复合主键 `(model_id, file_name)`）

支持方法：

| 方法 | 说明 |
|------|------|
| `upsert(model_id, file_name, url, bytes, total, status, error)` | 插入或更新下载记录 |
| `update_progress(model_id, file_name, bytes, total)` | 更新下载进度 |
| `find_by_model(model_id) -> Vec<DownloadRecord>` | 按模型查找所有下载记录 |
| `find_incomplete() -> Vec<DownloadRecord>` | 查找未完成的下载（用于启动恢复） |
| `list_all() -> Vec<DownloadRecord>` | 列出所有下载记录 |
| `delete(model_id, file_name)` | 删除单条记录 |
| `delete_by_model(model_id)` | 删除某个模型的所有记录 |
